## Loading performance

The first local Lighthouse audit found CLS 0.654 and TBT 840 ms, with a performance score of 42. PerformanceObserver reproduced the footer and saved-point controls being displaced during loading. Bootup diagnostics identified eager offscreen MapLibre initialization as the main CPU cost. Reserving loading space and observing map visibility reduced CLS to 0.0001 and TBT to 10 ms; performance scored 88. The simulated mobile LCP remains 3.8 seconds and can improve further. These are local lab results, not production traffic or field Core Web Vitals.

Those earlier geographic-refinement reports are `.impeccable/review/refinement-lighthouse.json` and `refinement-lighthouse-after.json`. That follow-up ran while the browser suite was active, so timings include local machine contention; layout-shift evidence and the regression assertions independently confirm the fix.

The previous layout's retailer-overview audit, `.impeccable/review/overview-lighthouse.json`, ran against that build at 14:17 UTC: performance 87, accessibility 100, best practices 100, CLS 0.013, TBT 20 ms, LCP 4.0 seconds. The first audit of the daily-summary layout measured CLS 0.102: on phones the modelled-now line and retrieval age wrapped to two lines only after data arrived, pushing the content down. Both lines are now reserved while loading, the meta line again swaps coordinates for the timezone instead of adding a field, and placeholders match the measured summary (about 150px plus 60px per local day), hourly (650px) and aside (800px) heights. The fourth review re-measured them for the tiles and the heading that now stays outside the placeholder (see the table above). The repeat audit, `.impeccable/review/retailer-lighthouse.json`, measured CLS 0 with the scores in the table above. These are local lab results, not production field metrics.

## Build and dependency limitations

MapLibre is a deliberately separate, large browser chunk (roughly 284 kB gzipped, plus its worker). The build reports the size warning and vinext's own ineffective-dynamic-import/static-route-classification notices. The app's dynamic features were verified in workerd rather than inferred from static route labels.

Updated 16 October 2026: `fflate` 0.7.5 remains pinned. The vulnerable `fast-glob → micromatch → braces` build-time chain has been removed through a version-scoped adapter to Vite's existing `tinyglobby`. The plugin's actual synchronous glob call is covered by compatibility tests. `npm audit` reports no known vulnerabilities, and the release script permits no advisory exceptions. This is a dependency check, not a security certification. [Current security controls](markets/security.md).

The user explicitly chose the bundled Natural Earth basemap. No MapTiler key was configured, and live MapTiler tiles are not claimed tested. Production KV is provisioned; provider commercial entitlement remains a separate operating requirement. Local API log lines were checked for route/outcome information without location query values; current hosted privacy controls are described in the [security assessment](markets/security.md).

Preview must be restarted after a rebuild: keeping an older Worker manifest running while replacing hashed assets can create 404s. Final checks used a freshly restarted preview with one consistent build.
